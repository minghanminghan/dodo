# Dodo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A markdown doc store (Next.js + SQLite + agent CLI + offline phone UI) built and deployed like sparrow.

**Architecture:** One Next.js app. `src/core` holds the DB and doc operations, shared by API routes and the CLI. The server keeps an in-memory index of all docs (like sparrow's `src/server/state.ts`, without SSE). The browser caches the full index in IndexedDB, renders and edits locally, and sends offline creates/edits through an outbox.

**Tech Stack:** Next.js 16, React 19, TypeScript, `node:sqlite` (FTS5 trigram), tsup, vitest, zustand, idb-keyval, fuse.js, react-markdown + remark-gfm + rehype-sanitize + rehype-highlight, CodeMirror 6, Tailwind 4, pnpm, Node 24.

**Spec:** `docs/superpowers/specs/2026-11-02-dodo-design.md`

**Reference repo:** `~/Desktop/personal/productivity` (sparrow), called `SP/` below. "Copy `SP/x`" means copy the file and rename sparrow → dodo, `SPARROW_` → `DODO_`, `X-Sparrow-` → `X-Dodo-`, `KbError` → `DodoError`, `__kb` → `__dodo`, `useKb` → `useDodo`, then delete what dodo does not use (tasks, columns, links, comments, mentions, SSE).

## Global Constraints

- Follow `SP/CLAUDE.md`: simple code, minimal comments and tests (none where possible), docblocks under 12 lines, conventional commits. Tests below are the only ones to write.
- Node 24+, pnpm, same dependency versions as `SP/package.json` where shared.
- Copy sparrow's code into dodo. No shared package, no change to sparrow.
- Env vars: `DODO_DB` (default `~/.dodo/dodo.db`), `DODO_FILES` (default `<db dir>/files`), `DODO_BACKUPS`, `DODO_URL`.
- Prod URL `https://dodo.andrewminghanjiang.com`, server `127.0.0.1:3420`, tailnet only, no login.
- Files: 25 MB max each.
- Editing and rendering run in the browser. Search (full-text and fuzzy) runs on the server.
- Offline: only create and edit-text. Moves, deletes, project changes and uploads need a signal and the UI says so.
- No version history, no `$EDITOR` flow, no folder sync, no links to sparrow, no import of existing docs.

## Review Focus

1. A retried write after a lost response (the first write landed) returns success and makes no conflict copy — test in Task 2.
2. Paths typed by people and agents (`Deploy/Mini-PC/`, `deploy/runbook.md`, `../x`, `a//b`) are normalized or rejected with a usage error — test in Task 1.
3. Search for 1–2 characters, or with FTS syntax (`"`, `-`, `*`, `AND`), returns results or `[]`, never a 500 — test in Task 4.
4. Two offline edits to one doc before the signal returns become one outbox entry that keeps the first base hash — test in Task 7.
5. Moving a doc or folder onto an existing path fails with `conflict` and changes nothing — test in Task 2.

```sql
CREATE TABLE docs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  path TEXT NOT NULL,
  body TEXT NOT NULL DEFAULT '',
  created TEXT NOT NULL,
  updated TEXT NOT NULL,
  client_id TEXT,
  deleted_at TEXT
);
CREATE UNIQUE INDEX docs_path ON docs (path) WHERE deleted_at IS NULL;
CREATE UNIQUE INDEX docs_client_id ON docs (client_id) WHERE client_id IS NOT NULL;
CREATE TABLE doc_projects (doc_id INTEGER NOT NULL REFERENCES docs(id), project TEXT NOT NULL, PRIMARY KEY (doc_id, project));
CREATE TABLE files (id TEXT PRIMARY KEY, doc_id INTEGER NOT NULL REFERENCES docs(id), filename TEXT NOT NULL, mime TEXT NOT NULL, size INTEGER NOT NULL, created TEXT NOT NULL);
CREATE INDEX files_doc ON files (doc_id);
CREATE VIRTUAL TABLE docs_fts USING fts5(path, body, content='docs', content_rowid='id', tokenize='trigram');
```

plus the three standard external-content triggers (`AFTER INSERT`, `AFTER DELETE`, `AFTER UPDATE`) that keep `docs_fts` in sync. Soft-deleted rows stay in FTS; search filters them out.

### Task 2: Doc operations

**Files:**
- Create: `src/core/docs.ts`
- Test: `src/core/docs.test.ts`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `type SaveResult = { doc: Doc; conflictOf?: string }` — `conflictOf` is set when the body was saved as a conflict copy instead; `doc` is then the copy.
  - `readDoc(db, path): Doc` (`not_found` if missing)
  - `loadIndex(db): DocIndex`
  - `createDoc(db, input: { path: string; body: string; projects?: string[]; clientId?: string; onConflict?: 'copy' }): SaveResult`
  - `writeDoc(db, path, input: { body: string; baseHash: string; clientId?: string; onConflict?: 'copy' }): SaveResult`
  - `movePath(db, from: string, to: string): string[]` (new paths moved)
  - `deleteDoc(db, path): void` (soft delete, sets `deleted_at`)
  - `setProjects(db, path, projects: string[]): Doc`
  - `now()` copied from `SP/src/core/ops.ts`

Behavior the tests pin:
- `createDoc` with a `clientId` already used returns that doc (sparrow's `createTask` pattern).
- `createDoc` on a taken path: `conflict` error, or with `onConflict: 'copy'` a copy.
- `writeDoc`: if `hash(current.body) === hash(input.body)` it succeeds with no change (retry after a lost response). Else if `baseHash !== current.bodyHash`: `conflict` error, or with `onConflict: 'copy'` a copy.
- Conflict copy: path `<path>.conflict-<n>` with the smallest free `n` from 1, same projects, `client_id = clientId`. A retry with the same `clientId` returns the existing copy.
- `movePath` moves the doc at `from` and every doc under `from/`; files follow (they hang off `doc_id`). Any target taken → `conflict`, nothing moved. Neither exists → `not_found`.
- A deleted path can be created again.

### Task 4: Search

**Files:**
- Create: `src/core/search.ts`
- Test: `src/core/search.test.ts`

**Interfaces:**
- Consumes: `Db`, `DocIndex`.
- Produces: `type Hit = { path: string; title: string; snippet?: string }`, `searchDocs(db, index: DocIndex, q: string, opts?: { project?: string; limit?: number }): Hit[]` (default limit 20).

Method (decided):
- Fuzzy: `fuse.js` over `index.docs` with keys `path` and `title`, `threshold: 0.4`. Runs in memory on the server.
- Full text: for queries of 3+ characters, `docs_fts MATCH ?` with the query wrapped as a single quoted phrase (internal `"` doubled), joined to `docs` where `deleted_at IS NULL`, ordered by `rank`, with `snippet(docs_fts, 1, '', '', '…', 12)`.
- Merge: fuzzy hits first, then full-text hits, deduped by path. Project filter applies to both.

**Files:**

- Consumes: the HTTP API.
- Produces:
  - `type OutboxEntry = { clientId: string; kind: 'create' | 'write'; path: string; body: string; baseHash?: string; projects?: string[]; createdAt: number; error?: string }`
  - `queueEdit(entries: OutboxEntry[], next: Omit<OutboxEntry, 'clientId' | 'createdAt'>): OutboxEntry[]` — one entry per path: if one exists, replace its `body` and keep its `kind`, `baseHash` and `clientId`.

  - `loadOutbox`, `saveOutbox`, `loadCachedIndex`, `saveCachedIndex`.
  - Store `useDodo`: `{ index, rev, offline, outbox, conflicts: { path: string; copy: string }[], load(), refreshIndex(), saveEdit(path, body, baseHash), createDoc(path, body, projects), flush() }`. The docs shown are the index with pending outbox bodies laid over it. `refreshIndex` uses `If-None-Match`; it runs on load, on `online`, and on `visibilitychange` to visible. `flush` runs after each refresh that succeeds.
